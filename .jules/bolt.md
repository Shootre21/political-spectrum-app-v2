## 2025-05-18 - Replacing N+1 DB Queries with Batch Check & createMany in storeArticlesInDatabase
**Learning:** In `src/lib/news-fetcher.ts`, an N+1 performance bottleneck existed where each incoming RSS article was checked for uniqueness via `db.article.findFirst` before being inserted via `db.article.create`. This sequential approach causes heavy database latency, particularly since articles are routinely polled and stored. Using a single `findMany({ where: { url: { in: urlsToCheck } } })` combined with `createMany` reduces N database queries to 2. However, intra-batch deduplication via `Map` (or `Set`) prior to insertion is strictly required because Prisma's `createMany` on SQLite does not natively support `skipDuplicates`, and duplicate incoming URLs would crash the batch operation.
**Action:** Always scrutinize loops executing sequential database operations. Implement batch checks with the `in` operator, ensuring data deduplication is handled in-memory beforehand to avoid unique constraint violations, and provide a sequential fallback for robustness.
