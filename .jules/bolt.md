## 2024-05-18 - Fast String Matching vs Regex
**Learning:** In Node.js/Bun, repeatedly creating `new RegExp()` inside a hot loop (like text parsing) is a major performance bottleneck due to regex compilation overhead. While regex is powerful, replacing `new RegExp(..., 'gi')` instantiations with module-scoped, pre-lowercased string arrays and optimized `String.prototype.indexOf` while-loops yields significant execution speedups (e.g., >3x faster for score calculation).
**Action:** When implementing text analysis or search functions across static lexicons, prefer pre-processing arrays (e.g., lowercasing them once at module scope) and using `indexOf` over dynamic inline regex instantiations. Remember to correctly advance the `indexOf` position pointer by the length of the matched term (`pos += term.length`) to replicate non-overlapping regex match behavior and prevent infinite loops (`if (term.length === 0) continue`).
