## 2024-05-30 - Optimize N+1 database queries for batched insertion in SQLite
**Learning:** Direct SQLite benchmarking in this restricted environment indicates that replacing 100 individual existence queries (N+1) with a single batched `IN` query yields approximately a 60x performance improvement (e.g., reducing execution time from ~370ms to ~6ms). Also, Prisma's `createMany` method on SQLite does not support `skipDuplicates`, so deduplication must be handled manually (in memory for intra-batch and via the batched `IN` query for existing records) before falling back to sequential insertion for robustness if batched insert fails.
**Action:** When inserting multiple records that may already exist, use `findMany` with the `in` operator to identify existing items, deduplicate the payload in-memory (using `Array.from(new Map(...).values())`), and then use `createMany` to batch insert the new records. Always include a sequential fallback in a catch block for robustness.
