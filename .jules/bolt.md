## 2024-07-22 - Optimize Regex Instantiations in Hot Paths
**Learning:** In string-heavy text analysis loops (like scoring articles for bias/emotion against large lexicons), repeatedly instantiating regular expressions (`new RegExp(term, 'gi')`) and using `.match()` is significantly slower than using an `indexOf`-based while-loop for occurrence counting in Node.js/Bun environments. Additionally, flattening and pre-lowercasing the term arrays at module scope prevents repeated memory allocations in `.map()` and `.toLowerCase()` operations.
**Action:** When performing simple case-insensitive text existence checks or frequency counting across arrays of static terms, prefer module-scoped, pre-lowercased arrays and custom `indexOf` wrappers instead of inline regex replacements to maximize string operation throughput.
