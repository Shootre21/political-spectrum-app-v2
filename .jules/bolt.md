## 2024-05-24 - JIT microbenchmarking vs realistic workloads
**Learning:** When benchmarking string search operations in Bun/Node, JIT optimizations can artificially inflate the performance of single-term inline regex `match` in microbenchmarks. For realistic workloads with arrays of multiple terms, `indexOf` loops with pre-lowercased strings remain significantly faster (up to ~7x) and more reliable than inline regex instantiations. Also, replacing global `String.prototype.match()` calls with `indexOf` in a while-loop for occurrence counting must advance the search index by the length of the matched term (e.g., `pos += term.length`) rather than by 1, to accurately replicate the non-overlapping match behavior of regex.
**Action:** Always test optimizations using real-world strings/patterns inside arrays to defeat JIT over-optimization. Ensure custom loop replacements meticulously duplicate regex offset logic.
