## 2024-05-14 - Inline Regex Instantiation Overhead
**Learning:** Dynamically compiling `RegExp` objects inside hot loops (like in `calculateFramingScore` and `calculateEmotionalScore` where it iterated over lexicon arrays) creates significant performance bottlenecks due to compilation overhead and `String.prototype.match()` memory allocation.
**Action:** Replace dynamic regexes inside hot text analysis loops with manual `indexOf` `while` loops. Advance the index by the search term length (`pos += length`) to perfectly mimic global regex non-overlapping matching behavior, while explicitly handling zero-length search terms (`length === 0`). Also, ensure proper inline code comments are added explaining *why* the optimization was applied so code reviewers understand the context.
