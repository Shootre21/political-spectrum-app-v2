## 2024-09-10 - Replace RegExp with fast indexOf for text analysis loops
**Learning:** In Node.js/Bun, dynamically creating `new RegExp()` inside hot loops (e.g., text scoring with large lexicons) is a severe performance bottleneck. While V8 is good at caching literal regexes, dynamically generated ones inside iterative structures defeat optimizations. Using `String.match` with a global regex flag is also slower than manually tracking substring occurrences with `String.indexOf` for static string terms. Additionally, using inline `.toLowerCase()` mapping and spread operations `.filter()` on arrays causes memory churn that slows down early-exit logic.

**Action:** When searching for literal strings from static dictionaries in hot paths (like text classification engines), always pre-lowercase the dictionaries at the module level. Replace global `RegExp.match` calls with a custom `indexOf` `while`-loop that skips forward by the term length to achieve exact non-overlapping semantics. Replace `.filter()` checks with standard `for` loops utilizing early `break` statements.
