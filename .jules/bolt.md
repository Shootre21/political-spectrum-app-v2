## 2025-03-01 - Microbenchmark Reality Checks for Regex vs indexOf
**Learning:** When benchmarking string search operations in Bun/Node, simple microbenchmarks comparing a single-term `new RegExp(term, 'gi')` against `indexOf` can be deeply misleading due to aggressive JIT caching of the literal string compilation within tight loops. However, when tested against realistic arrays of multiple terms (e.g., scanning 100 lexicon terms per text), the JIT cannot optimize away the inline regex compilation overhead, and the `indexOf`-based while-loop algorithm (combined with module-scoped, pre-lowercased target terms) proves to be ~2-3x faster.
**Action:** Always structure backend performance microbenchmarks to simulate realistic memory access patterns (e.g., iterating through multiple different array items) rather than hammering a single static term. Never trust a single-variable tight loop to accurately represent real-world regex engine overhead.
