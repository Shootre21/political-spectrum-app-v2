## 2024-05-30 - High overhead of `RegExp` instantiation and array filtering in hot paths

**Learning:** In the `src/lib/lexicons.ts` file, several functions like `detectTopic`, `calculateFramingScore`, and `calculateEmotionalScore` are executed frequently during the bias analysis of articles. These functions heavily rely on dynamically instantiating regular expressions (`new RegExp(..., 'gi')`) inside loops and using `array.filter` with `includes` over large lexicon arrays. This dynamically creates many RegExp objects and performs costly repeated array operations, which becomes a bottleneck in Node.js/Bun micro-benchmarks. Specifically, `detectTopic` uses `allTerms.filter(...)`, making it search all terms even after a match is found. `calculateFramingScore` and `calculateEmotionalScore` use regex instantiation.

**Action:** Pre-calculate and cache lowercased versions of the lexicons at the module level. Replace dynamic `new RegExp` instantiations inside loops with a `while` loop using `indexOf(term, pos)` for fast occurrence counting, as string searching without regex compilation is significantly faster. For existence checking in `detectTopic`, replace `array.filter(...).length > 0` with a standard `for...of` loop containing a `break` statement to exit early upon the first match. This avoids memory allocation for intermediate arrays and speeds up execution significantly.
