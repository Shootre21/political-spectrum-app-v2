## 2025-02-28 - RegExp Instantiation Overhead in Hot Loops
**Learning:** Instantiating `new RegExp()` inside hot loops (like in the text framing analysis engine) is a massive performance bottleneck. The `String.prototype.match()` method resets the global (`gi`) regex state (`lastIndex`), so pre-compiled regex objects can be safely cached globally and reused. Also, `toLowerCase()` on massive text blocks on every execution is redundant if using `/i` case-insensitive regex flags or if the original input lexicons are pre-computed into arrays of lowercased strings at module level.
**Action:** Always pre-compile regexes at the module scope for repeated text analysis, and pre-cache mapped arrays of lowercased static lexicons rather than calling `.toLowerCase()` continuously in hot loops.
