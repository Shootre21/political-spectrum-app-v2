## 2024-06-06 - Prisma Native Aggregations vs findMany
**Learning:** Using Prisma's `findMany` to pull all database records into memory for analytical operations (counting, grouping, averaging) creates an O(N) memory bottleneck. Always utilize native database aggregations (`aggregate`, `groupBy`, and parallel `count` queries) to achieve O(1) memory consumption and reduce data transfer overhead. Wait, memory says: "Prisma's native `groupBy` does not easily support grouping by date parts (e.g., day, month) when using SQLite. Time-series data aggregation (like in `getTimeSeriesData`) may require fetching bounded datasets for in-memory processing or using raw SQL." AND "The database client in `src/lib/db.ts` uses `createEmptyResultProxy` to handle unavailable states; it returns `[]` for `findMany`, `0` for `count`, `null` for `findFirst`/`findUnique`, `{}` for `aggregate`/`groupBy`, and throws an `Error` for mutations (`create`, `update`, `delete`, etc.)."
**Action:** Optimize in-memory O(N) aggregations (e.g. `getAnalyticsOverview`) using Prisma's native `aggregate` and `groupBy` where possible, avoiding it for Date parsing in SQLite.
