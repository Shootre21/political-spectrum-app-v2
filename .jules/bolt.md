## $(date +%Y-%m-%d) - Optimize Regex usage in string-matching text analysis engine
**Learning:** In highly repetitive string matching algorithms (like the lexicon text analysis engine), executing multiple `.toLowerCase()` operations and instantiating `RegExp` objects inside function calls incurs significant runtime overhead. Additionally, using standard loops with early returns (`break`) is much faster than running `Array.prototype.filter` across entire collections when merely checking for existence. When compiling shared `RegExp` objects, using the `g` flag with `String.prototype.match()` resets the internal `lastIndex` safely on each execution and prevents false negatives, allowing instances to be reused across function calls.
**Action:** When working on text analysis patterns, pre-compile `.toLowerCase()` target strings and `RegExp` objects as module-scoped static variables and employ short-circuiting standard loops instead of full array iterations for existence checks. Always use `String.prototype.match()` instead of `RegExp.prototype.test()` when sharing compiled `g` regex objects.
