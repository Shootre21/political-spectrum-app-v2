## 2024-06-17 - Fast String Matching with indexOf vs RegExp in Hot Loops
**Learning:** In Node/Bun, dynamically instantiating `new RegExp(term, 'gi')` inside text-processing hot loops creates severe execution overhead. Furthermore, extracting regular expressions into module-level arrays offers only marginal improvement if the matching loop relies heavily on the stateful `.match()` method for counting. By replacing regex processing entirely with an optimized module-scoped object containing pre-lowercased search arrays and leveraging a custom `indexOf` string-counting loop, execution time can be massively reduced (measured ~40% faster in isolated benchmarks).
**Action:** When performing exhaustive string classification/counting against static lexicons inside hot loops, bypass regular expressions and `.filter` spreading. Instead, pre-cache the lexicons in lowercase at the module level and use `indexOf` while-loops or basic `for` loops with early `break` statements.
