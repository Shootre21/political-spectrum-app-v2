## 2025-02-24 - Database N+1 Query Optimization in Batch Operations
**Learning:** In standard node environment running SQLite via Prisma, running individual `findFirst` and `create` queries within a `for...of` loop creates a massive N+1 bottleneck, taking significantly longer than batched operations due to context switching overhead and transaction volume.
**Action:** Always replace array iterations doing `findFirst` existence checks with a single `findMany` using the `{ in: [...] }` operator mapped over unique keys, followed by an in-memory `Set` filtering of what needs to be created, and then a bulk `createMany` for insertions. Always include an `Array.from(new Map())` deduplication step first to prevent intra-batch duplicate constraint errors when applying this optimization.
